# 对标叙事参考：科技米线（Ai 版）

## 本 Skill 的使用边界

用户的视频是“场景痛点 + Skill 解决方案 + 成品展示 + 极简录屏教学”。因此只把博主的叙事机制迁移到教学流程，不复刻他的 AI 原理讲解、具体口头禅、品牌词或原句。口播稿必须先让观众认出具体问题，再看到成品价值，最后跟着录屏完成最短路线：

`场景痛点 → “这个时候需要【Skill】” → 展示成品 → 首先安装 Skill → 调用 → 提供材料 → 确定生成 → 注意事项 → 回扣痛点 → 开源 CTA`

这条路线是交付硬约束。博主视频里的“去下一个地方”在这里对应“做下一步操作”；每次转场都要说明刚才得到什么，以及为什么要继续。

开场顺序不能调换：先说具体场景痛点，再说“这个时候你就需要【Skill】”，然后展示成品，最后才进入录屏。教程必须用“首先”开头。

模板中的 Skill 名称、主题和段落标题必须替换成当前任务的真实输入，不能原样保留“口播剧本 Skill”等旧示例。

这份参考只提炼用户提供视频中可观察的叙事机制，不复制博主的品牌、原句、标题、人设或具体素材。作者的完整拉片保存在其本机工作区；本 Skill 的可移植叙事规则以本文件为准。

## 核心结构

重点视频《GPT6 把我的个人网站做成了开放世界！！帅爆》采用“作品试玩式发布”，其他样本还使用痛点质疑、数字冲突和观点判断等开场。对 Skill 教学视频，只迁移“先让观众知道为什么值得看，再用画面证明结果”的机制，不直接套用作品展示视频的成品先行顺序。

本 Skill 教学视频的固定骨架是：

`具体场景痛点 → “这个时候需要【Skill】” → 成品展示 → 首先安装 Skill → 调用 → 提供材料 → 点击确定生成 → 注意事项 → 回扣痛点 → 开源 CTA`

博主案例中的“去下一个地方”在这里只对应教程中的下一个关键动作，不扩展成智能体协作、返工过程或长篇探索。每个动作只说明它为什么能得到当前成品。

## 口播循环

每一站用 1—4 句完成：

1. **反应**：对刚刚发生的动作做即时、克制的反应。
2. **发生**：说清刚才做了什么或看到了什么。
3. **证明**：指出它证明了哪个具体判断，或承认哪里仍不够。
4. **下一站**：告诉观众接下来为什么要做另一个操作。

示例句式（仅作结构提示）：

```text
我去，这里刚刚真的发生了【动作】。
它不是只把【表面结果】做出来，而是连【具体细节】也保留了。
但这只能证明【有限判断】，我们再去看【下一站】，验证【下一个问题】。
```

## 对标样本的可迁移节拍

- 痛点型视频：第一句直接陈述具体问题，再给解决方案。
- 作品型视频：可以成品先行，但不覆盖本 Skill 的痛点先行硬约束。
- 工具型视频：结果和操作互相证明，教程只保留会影响结果的动作。
- 教程型视频：用最短路径让观众复现，不把内部原理当成内容主体。
- 结尾：回到开头痛点，说清 Skill 解决了什么，再接固定开源 CTA。

## 口播逐条分析的证据等级

- **可确认口播**：视频音频转写、画面字幕或公开简介明确出现的句子。可以总结其句式和因果，但不复制原句。
- **画面对应口播功能**：能看到动作和字幕功能，但听不清完整音频。只能写“这段口播在解释什么”，不能声称是逐字稿。
- **结构推断**：根据多个样本归纳出的节奏、转场和证明方式。只能作为生成规则。

本地拉片已经覆盖 9 条可下载视频和重点视频的逐秒抽帧；其余主页样本的标题、简介和时长不能冒充逐帧或逐字证据。生成新稿时优先采用结构推断，再用本次 Deep Research 和用户实际录屏结果填充事实。

## 教学版口播模板

```text
[真人开场｜约 X 秒]
做【具体任务】时，最难的不是【表面动作】，而是【具体困难】；如果靠自己一点点拼，通常会卡在【时间/信息/执行问题】，最后造成【明确损失】。

[解决方案承接]
这个时候你就需要【Skill】来帮你【具体解决动作】。今天我从下载开始，完整跑一遍它到底能不能解决这个问题。

[成品展示]
先看一下它最后生成的【成品】，这里面有【成品中的关键内容】。接下来用最简单的几步，把它跑出来。

[录屏旁白｜教程]
首先，把这个 Skill 的链接输入进去，完成安装。然后调用 Skill，把【素材或材料】发给它，点击确定，等它直接生成成品。它会先整理相关资料再生成，这部分不用展开讲。

[结尾总结｜注意事项、解决结果与开源 CTA]
这里有一个注意点：【真实限制】。整体来说，它把【开头痛点】变成了【最终结果】，省掉了【具体重复工作】。整套 Skill 我已经全部开源，感兴趣的评论区打上分享，我是 AX，我们下期见。

## 时长与口播角色

- 默认 60—90 秒；只有成品展示或注意事项确实较多时才延长到约 2 分钟。
- 不为塞进时长而加入智能体协作、返工或内部研究过程。
- 真人开场：痛点、Skill 承接、结果期待。
- 录屏旁白：当前动作、证据、问题、下一步。
- 结尾总结：前后对比、量化收益、限制。
```

## 写作边界

- 拉片里的“推断”不能写成已观测事实；如果只看到了抽样画面，就标为结构参考。
- 任何具体数字、功能、性能和时间都要由本次 Deep Research 或用户提供的素材支持。
- 没有真实失败时，不强行制造失败；可以用“限制尚未验证”或“下一步要测试”形成诚实悬念。
- 只迁移节奏和因果关系，不模仿可识别的口头禅和原句。
