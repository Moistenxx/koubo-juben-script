# 对标叙事参考：科技米线（Ai 版）

## 本 Skill 的使用边界

用户的视频是“短真人开场 + 屏幕录制教学”。因此只把博主的叙事机制迁移到教学流程，不复刻他的 AI 原理讲解、具体口头禅、品牌词或原句。口播稿必须让观众跟着录屏完成一条真实路线：

`真人抛出结果和主题 → 打开智能体 → 打开 Skill → 输入任务 → 等待调研 → 生成初稿 → 按案例逻辑修改 → 展示最终稿`

这条路线是交付硬约束。博主视频里的“去下一个地方”在这里对应“做下一步操作”；每次转场都要说明刚才得到什么，以及为什么要继续。

这份参考只提炼用户提供视频中可观察的叙事机制，不复制博主的品牌、原句、标题、人设或具体素材。作者的完整拉片保存在其本机工作区；本 Skill 的可移植叙事规则以本文件为准。

## 核心结构

重点视频《GPT6 把我的个人网站做成了开放世界！！帅爆》采用“作品试玩式发布”：观众先看到成品和强烈反应，再跟着创作者沿地图/场景移动。每一站通过一个可见动作证明一个卖点，口播解释动作的意义，再把观众带到下一站。

可迁移的骨架是：

`惊喜/结果 → 任务转换 → 路线探索 → 动作证据 → 个人连接 → 真实限制或设备验证 → 细节彩蛋`

不是所有主题都要做成游戏或作品集；“地图、车辆、区域”要替换成该主题真实存在的浏览路线、步骤、案例、现场或对比。

## 口播循环

每一站用 1—4 句完成：

1. **反应**：对刚刚发生的动作做即时、克制的反应。
2. **发生**：说清刚才做了什么或看到了什么。
3. **证明**：指出它证明了哪个具体判断，或承认哪里仍不够。
4. **下一站**：告诉观众接下来为什么要做另一个操作。

示例句式（仅作结构提示）：

```text
我去，这里刚刚真的发生了【动作】。
它不是只把【表面结果】做出来，而是连【具体细节】也保留了。
但这只能证明【有限判断】，我们再去看【下一站】，验证【下一个问题】。
```

## 重点视频的可复用节拍

- 开头：成品/结果蒙太奇，立即抛出“我把什么变成什么”。
- 前段：一个简单动作证明它可操作、可使用或确实发生。
- 中段：沿路线展开 2—4 个不同性质的证据，避免连续念功能名。
- 转折：把展示对象连回创作者的履历、任务背景或观众痛点。
- 后段：做一次真实使用、移动端、兼容性、边界或反差验证。
- 结尾：回到一个仍然有新信息的细节/彩蛋，用判断收束，而不是空泛 CTA。

## 口播逐条分析的证据等级

- **可确认口播**：视频音频转写、画面字幕或公开简介明确出现的句子。可以总结其句式和因果，但不复制原句。
- **画面对应口播功能**：能看到动作和字幕功能，但听不清完整音频。只能写“这段口播在解释什么”，不能声称是逐字稿。
- **结构推断**：根据多个样本归纳出的节奏、转场和证明方式。只能作为生成规则。

本地拉片已经覆盖 9 条可下载视频和重点视频的逐秒抽帧；其余主页样本的标题、简介和时长不能冒充逐帧或逐字证据。生成新稿时优先采用结构推断，再用本次 Deep Research 和用户实际录屏结果填充事实。

## 教学版口播模板

```text
[真人开场]
我今天要用【Skill】从零做出【成品】，先看最后能不能得到【可观察结果】。

[打开入口]
先打开智能体，再打开口播剧本 Skill。这里的重点不是让它讲原理，而是让它按一条真实流程把稿子做出来。

[输入任务]
我把【主题、受众、平台、时长、语气、素材】一次交代清楚，接下来让它先去做调研。

[研究到初稿]
它先把相关事实和来源整理出来，再开始写稿。这样后面的判断有依据，遇到没验证的地方也会留下待补。

[按案例打磨]
初稿出来以后，我只保留这条推进链：先给结果，然后让观众跟着操作走；每一步做一个动作、给一个证据，再自然带到下一步。

[最终稿]
现在这版才是可以直接录音的口播稿。它把真人开场、录屏步骤、真实结果和限制连在了一起，哪里还没实测就明确标出来。
```

## 写作边界

- 拉片里的“推断”不能写成已观测事实；如果只看到了抽样画面，就标为结构参考。
- 任何具体数字、功能、性能和时间都要由本次 Deep Research 或用户提供的素材支持。
- 没有真实失败时，不强行制造失败；可以用“限制尚未验证”或“下一步要测试”形成诚实悬念。
- 只迁移节奏和因果关系，不模仿可识别的口头禅和原句。
