# 对标叙事参考：科技米线（Ai 版）

这份参考只提炼用户提供视频中可观察的叙事机制，不复制博主的品牌、原句、标题、人设或具体素材。作者的完整拉片保存在其本机工作区；本 Skill 的可移植叙事规则以本文件为准。

## 核心结构

重点视频《GPT6 把我的个人网站做成了开放世界！！帅爆》采用“作品试玩式发布”：观众先看到成品和强烈反应，再跟着创作者沿地图/场景移动。每一站通过一个可见动作证明一个卖点，口播解释动作的意义，再把观众带到下一站。

可迁移的骨架是：

`惊喜/结果 → 任务转换 → 路线探索 → 动作证据 → 个人连接 → 真实限制或设备验证 → 细节彩蛋`

不是所有主题都要做成游戏或作品集；“地图、车辆、区域”要替换成该主题真实存在的浏览路线、步骤、案例、现场或对比。

## 口播循环

每一站用 1—4 句完成：

1. **反应**：对刚刚发生的动作做即时、克制的反应。
2. **发生**：说清刚才做了什么或看到了什么。
3. **证明**：指出它证明了哪个具体判断，或承认哪里仍不够。
4. **下一站**：告诉观众接下来为什么要看另一个动作。

示例句式（仅作结构提示）：

```text
我去，这里刚刚真的发生了【动作】。
它不是只把【表面结果】做出来，而是连【具体细节】也保留了。
但这只能证明【有限判断】，我们再去看【下一站】，验证【下一个问题】。
```

## 重点视频的可复用节拍

- 开头：成品/结果蒙太奇，立即抛出“我把什么变成什么”。
- 前段：一个简单动作证明它可操作、可使用或确实发生。
- 中段：沿路线展开 2—4 个不同性质的证据，避免连续念功能名。
- 转折：把展示对象连回创作者的履历、任务背景或观众痛点。
- 后段：做一次真实使用、移动端、兼容性、边界或反差验证。
- 结尾：回到一个仍然有新信息的细节/彩蛋，用判断收束，而不是空泛 CTA。

## 写作边界

- 拉片里的“推断”不能写成已观测事实；如果只看到了抽样画面，就标为结构参考。
- 任何具体数字、功能、性能和时间都要由本次 Deep Research 或用户提供的素材支持。
- 没有真实失败时，不强行制造失败；可以用“限制尚未验证”或“下一步要测试”形成诚实悬念。
- 只迁移节奏和因果关系，不模仿可识别的口头禅和原句。
