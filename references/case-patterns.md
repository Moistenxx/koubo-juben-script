# 视频拉片：Skill 教学口播的可迁移结构

## 证据范围

本参考来自用户提供的本地视频《codex完成自媒体全流程运营,5步实现ai短视频自动化 [千雪AI].mp4》。已完成时长、抽帧、OCR 和画面结构分析。由于本地语音转写未完成，下面把证据分为三类：

- **OCR/字幕可确认**：画面文字明确出现的表达和步骤。
- **画面对应功能**：画面能确认动作或结果，但不能证明完整逐字口播。
- **结构推断**：从多段节奏归纳出的写法，只能作为生成规则。

不要把这份拉片写成完整音频逐字稿，也不要上传视频、音频、抽帧或临时分析文件。

## 开场逻辑

视频先用强结果和价值判断抓住注意力，再连续抛出具体痛点：收藏夹有爆款但自己选题困难、脚本反复修改、剪辑做到凌晨。随后承接“这些工作可以在 Codex 里串成一套流程”，并承诺从一个账号链接开始，把选题、脚本、剪辑预览、封面和交付逐步做出来。

迁移到 Skill 教学时，保留“结果承诺 + 连续痛点 + 解决方案”节奏，但按用户要求把第一句改成直接痛点：先说任务、卡点和损失，再说“这个时候你就需要【Skill】”。成品展示放在方案之后。

## 教程推进

### 可确认的动作

画面能看到建立项目文件夹、放入历史脚本和素材、安装并调用研究 Skill、从账号链接分析近期内容、生成选题和脚本、制作剪辑预览与封面、复盘数据，并把个人脚本风格固化成可复用 Skill。

### 可迁移的节奏

每个步骤用短段完成四件事：

1. 说刚才做了什么。
2. 指出刚才得到的结果。
3. 说明这个结果为什么有用。
4. 告诉观众为什么进入下一步。

Skill 教学应压缩成四个可录屏动作：输入链接安装、调用、提供素材、点击确定生成。不要把每个按钮或内部智能体交互逐一念出来。

## 语言节奏

视频使用“第一步、第二步、完成之后、这里要注意”等路标词，并频繁用“但、不过、其实、并不是……而是……、真正关键的是……”制造转折。句子短，动作和判断交替出现；每段都把观众推向下一站，而不是连续罗列功能。

## 结尾逻辑

结尾先验收效果，再把价值升华为“人负责方向、观点和判断，AI 负责整理信息和执行”，最后提醒资料和开源内容，并用固定署名收束。对 Skill 教学，结尾应先说一至三条真实限制，再回扣开头痛点，说明省掉了什么重复劳动以及仍需人工判断什么，最后使用用户指定的开源 CTA。

## 使用边界

- 只学习叙事结构、节奏和因果推进，不复制博主原句、标题、人设、品牌或夸张数字。
- 没有音频逐字证据时，只能说“画面对应的口播功能”或“结构推断”。
- 所有具体功能、数字和效果必须由当前 Skill、用户素材或 Deep Research 支持。
- 默认目标是约 2 分钟、只含口播文字的 Skill 教学稿，不再采用旧的 60—90 秒作品试玩式模板。
